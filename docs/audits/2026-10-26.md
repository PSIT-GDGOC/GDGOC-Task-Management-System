# Code audit — 26 October 2026

Scope: the production TaskHub client, backend routes/services, session and permission boundaries, task workflows, history, notifications, background jobs, dependencies, and both frontend build pipelines. The separate admin frontend also received dependency, lint, pagination, storage, and task-team selection repairs.

## Confirmed issues fixed

| Area | Finding and remediation |
| --- | --- |
| Profile permissions | Self-edited position titles could turn a scoped ADMIN into a club manager. Position is now excluded from self-service profile updates; role grants remain in leadership workflows. |
| Browser trust | A wildcard accepted unrelated Vercel projects as trusted origins. Trust is limited to configured origins and the exact production hostname; production no longer trusts development localhost merely because password login is enabled. |
| Configuration | Production registration defaulted open, and a Redis hostname alone could bypass the TLS requirement. Registration now requires explicit production opt-in; unencrypted private Redis requires Render deployment context. |
| Public diagnostics | Removed unauthenticated GET routes that exposed mail configuration or sent mail to arbitrary recipients. Health and readiness checks remain available. |
| Leadership keys | New rotations require 12–200 characters, reject keys reused across positions, and create an audit event without copying the secret into it. New custom invitation keys also require at least 12 characters. Existing issued keys are preserved. |
| Frontend permissions | Client role mapping now uses server-confirmed club-management grants and real team memberships. Scoped admins receive the leadership workspace; self-declared titles and email fragments no longer grant a workspace or broaden assignment options. |
| History scope | Team admins can no longer audit unrelated teams through history endpoints. Executive club-wide access is preserved. |
| History data | Completed-history responses now include bounded real activity records. Active-work counters come from the task board rather than the completed-only history response. Tasks without deadlines are excluded from on-time percentages. |
| Team directory | Replaced fixed squad lists in dashboards/navigation with a cached, paginated database directory and actual rosters/leads. Custom teams work; invalid team URLs show an error rather than substituting another team. Directory failures have visible retry controls. |
| Team metrics | Team cards now calculate metrics from current tasks instead of an empty default list. |
| Activity | Removed fabricated approval/webhook/invitation entries and the mock activity fallback. Empty and unavailable feeds are distinguished. |
| Task actions | Detail dialogs await the server before closing, suppress duplicate submissions, and retain rejected-action errors. Member and lead callers propagate failures correctly. |
| Notifications | API failures are no longer swallowed. Failed read acknowledgements preserve unread state and show errors. Polling avoids overlapping calls, runs less often, skips hidden tabs, and discards late responses after an account change. |
| Email | Lifecycle templates escape user-supplied HTML and reject non-HTTP deliverable links. Brevo calls have a timeout. Production provider failures throw instead of reporting simulated success; failed reminders stay eligible for retry. |
| Transaction ordering | Assignment/submission/review emails are scheduled after the database transaction commits, preventing notifications for rolled-back changes. |
| Background scheduling | Deadline reminders use the shared BullMQ schedule instead of per-web-process timers, including external-worker deployments. Daily deduplication uses UTC. |
| OAuth recovery | Browser failures retain the selected portal and show sanitized messages; API clients receive proper error statuses. Login no longer double-decodes already parsed error query strings. |
| Rendering/storage | Added a render error recovery screen. Blocked preference storage no longer breaks successful sign-in, profile prompts, or tours. Profile-name failures are visible. |
| Loading performance | Dashboard pages load on demand. Initial client JavaScript decreased from about 501 KB to 331 KB before compression, rather than downloading every workspace up front. |
| Separate admin frontend | Repaired missing task-team selection, task pagination, optional preference storage, and unused declarations discovered by lint. |
| Tooling/dependencies | Added working frontend ESLint configurations and enabled lint in frontend CI. Updated React Router and Zod, and pinned the patched PostCSS selector parser through an override. |

## Verification

- Client: 61 tests; separate admin frontend: 3 tests.
- Backend unit tests: 29; PostgreSQL integration tests: 92; Redis/BullMQ integration tests: 8.
- Total: 193 passing tests. Type checks, lint and production builds passed for all workspaces.
- Full npm dependency audit: zero known vulnerabilities at the time of this audit.
- Browser verification used disposable local data: member sign-in, session restoration, task submission, lead approval, live roster and team scoping, invalid team URL, assignment choices, and executive analytics. No production task records were created or modified for testing.
- Screenshots: audit-lead-workflow.png and audit-analytics-verified.png in the task outputs folder.

## Operational limits

A source audit cannot guarantee there are no remaining defects. Google sign-in still needs deployment credentials if it is to be enabled. Free Render instance cold starts remain a hosting limitation. Email delivery after commit is best effort; provider outages now surface as failures rather than being reported as successful delivery.

Dependency advisories reviewed: [Zod resource exhaustion](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5), [React Router redirect handling](https://github.com/advisories/GHSA-wrjc-x8rr-h8h6), [PostCSS selector parsing](https://github.com/advisories/GHSA-rj75-hqrm-r3gf).
